platform: a website for desktop and mobile browsers [platforms]
platform: separate solutions for the website, API and database [repo-structure]
platform: the website never talks to the database directly; all data goes through ClothingAPI [anything-else]
solution: ClothingWebsite — website — github.com/example/clothing-website — ../clothing-website [solutions]
solution: ClothingAPI — API — github.com/example/clothing-api — ../clothing-api [solutions]
solution: ClothingDatabase — database — github.com/example/clothing-database — ../clothing-database [solutions]
infra: Azure Static Web Apps, Function App and SQL Server [hosting, database-technology]
infra: the AI writes Bicep in each solution's infra/ and the pipeline deploys it; a person manages the Key Vault and the SQL elastic pool [infrastructure-policy]
env: dev — the AI may deploy; production — people deploy after review [environments]
secrets: Azure Key Vault and GitHub Actions secrets, referenced by name only [infrastructure-policy]
rule: DRY — code repeated three times moves to a shared library [dev-rules]
rule: front-end page names use CamelCase [dev-rules]
floor: 90% line cover on new and changed code in the API and the website [testing]
floor: every decision — a permission check, a price calculation, an order-status change — has a test named after it [testing]
floor: no tests for generated clients, plain data holders or framework glue [testing]
floor: a change below 90% says so in its debt note; the number is never lowered [testing]
deliverable: 1 MVP — a customer can register, log in and see their account [deliverables]
deliverable: 2 Storefront — a customer can browse the range and view one item [deliverables]
deliverable: 3 Checkout — a customer can pay and get a receipt [deliverables]
security: JWT issued by ClothingAPI; access is by role [roles, ClothingAPI/application-spec.json#accessAndInterface.authType]
role: Admin, Manager, Customer [roles]
tier: cheapest model — simple, repetitive or low-risk tasks [cheapest-model]
tier: mid-range model — medium and advanced complexity features [mid-range-model]
tier: most capable model — complex, ambiguous or high-stakes bugs and features [most-capable-model]
tier: effort low for simple tasks, medium for everyday building, high for tricky or risky work [effort-levels]
